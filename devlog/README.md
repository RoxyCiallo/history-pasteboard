# 开发日志

每天一个文件：`YYYY-MM-DD.md`。用于记录当天做了什么、为什么、结果与遗留。

## 写什么

| 小节 | 内容 | 例 |
|---|---|---|
| 今日目标 | 当天计划推进的里程碑/任务 | `M1 数据层：db.py 建表 + CRUD` |
| 完成 | 已落地的事实 + 结果 | `db.py 的 upsert/list/purge 完成，测试 12 条全绿` |
| 待办 | 未做完、下一步要做的 | `补搜索转义用例` |
| 问题与风险 | 踩的坑、发现的隐患 | `剪贴板被远程桌面占用时读取失败，已加重试` |
| 明日计划 | 下一轮打算推进什么 | `M2 win32.py 剪贴板读写` |

## 怎么写

推荐用脚本（自动带时间戳、自动建文件）：

```powershell
python tools/devlog.py done "完成 db.py 建表与 CRUD"
python tools/devlog.py todo "补搜索转义用例"
python tools/devlog.py note "远程桌面下剪贴板偶发失败，已加重试"
python tools/devlog.py status
```

脚本行为：
- 写入 `devlog/YYYY-MM-DD.md`；文件不存在时用 `TEMPLATE.md` 创建。
- 条目格式 `- HH:MM 内容`，追加到对应小节末尾。
- `--date yesterday` 可补写昨天。

手工维护时，保持同样的文件命名与条目格式即可。

## 规则

1. **一天一个文件**，不跨天混写；跨天开工先建当天文件。
2. 只写事实、原因、结论，不写情绪与寒暄。
3. 完成项要带**可验证的结果**（测试通过数、验收条目、产物路径）。
4. 待办项必须可执行（动词开头）；否则不算待办。
5. 每轮开发收尾必须至少一条 `done` 和一条 `todo`（没有待办就写「无」）。
6. 不记录密码、密钥等敏感值。

## 与路线图的关系

- `docs/05-roadmap.md` 记录**计划与状态**（里程碑级）。
- `devlog/` 记录**过程**（当天级）。
- 两者在每轮收尾同时更新：先写日志，再把路线图状态改成 ✅/🟡。
